# 归因字典 · 旅程六阶段关键词表

## 使用原则

1. **顺序即优先级**：S1 → S6 依次匹配，命中即停止。这样「质量问题引发的退款」会判给 S5（上游）而非 S6（下游）。
2. **宁窄勿宽**：新增关键词时先想清楚它指代的环节，宽泛词（退款、售后、投诉）会拉低置信度。
3. **按类目扩展**：下面的默认规则以 3C 数码为基准，服饰/食品/家居类目需替换 S5 关键词。

---

## S1 售前呈现 —— 根责：运营部（商品/详情页）

消费者在下单前接收到的信息与实际不符。

```
描述不符、图文不符、规格不符、尺寸不符、大小不符、重量不符、颜色不符、色差、
夸大、虚假宣传、与描述、拍错、买错、参数标错、页面、详情、宣传
```

**类目扩展**
- 服饰：尺码不符、版型、起球、掉色、面料不符、实物与图片
- 食品：保质期、生产日期、配料表、分量不足、临期

## S2 下单支付 —— 根责：运营部（活动/价格）

```
价格、差价、优惠、券、活动、拍下、无法下单、超卖、改价、重复扣款
```

## S3 履约发货 —— 根责：仓储部门

```
延迟发货、虚假发货、未按约定、缺货、无货、漏发、少发、错发、发错、
揽收、发货慢、不发货、空包
```

**注意**：「缺货」归 S3 而非 S2 —— 库存没同步是运营的锅，但**已经卖出去发不出**是仓储/供应链的锅。

## S4 物流配送 —— 根责：仓储部门 / 承运商

```
物流、快递、派送、停滞、丢件、破损、配送、签收、运输、送货、驿站、派件
```

**判读**：若某承运商集中出问题 → 承运商考核；若全渠道均匀 → 打包方式或仓内操作问题。

## S5 收货体验 —— 根责：采购部 / 供应商（品质）

```
质量、损坏、坏了、故障、不能用、不好用、瑕疵、做工、异味、安装、不会用、
不清晰、噪音、掉线、断连、续航、失灵、开裂、生锈、缺少配件、功能
```

**类目扩展**
- 3C：黑屏、充不进电、连不上WiFi、录像丢失、卡顿、发热
- 服饰：开线、脱胶、异味、起球
- 家居：开裂、变形、晃动、螺丝缺失

## S6 售后维权 —— 根责：客服部（受理）

```
退款、退货、换货、运费、维修、客服、态度、服务差、差评、求助平台、
投诉、纠纷、介入、响应慢、不回复、旺旺、催
```

**⚠ 这一阶段的词大多是宽泛词**（退款、退货、维权、投诉、纠纷、求助平台），命中它们会被判为 **low 置信度**。

原因：一句「售后-退款问题」无法判断根因 —— 可能是质量（S5）、可能是发货慢（S3）、可能是描述不符（S1），只是最后都走到了退款。**受理在客服，根因在上游。**

---

## 置信度规则

| 置信度 | 判定 | 处理 |
|---|---|---|
| high | 命中具体词（质量、延迟发货、派送停滞…） | 可直接作为结论 |
| low | 只命中宽泛词（退款、售后、投诉…） | **必须人工回溯原始聊天/工单**，标注「待确认」 |
| none | 无任何命中 | 归入 S0 未分类，人工补录归因后重跑 |

宽泛词清单（命中即判 low）：
```
售后、退款问题、退款、退货、换货、维权、求助平台、投诉、纠纷
```

## 平台字段别名表

`analyze.py` 内置映射，支持以下命名（不区分中英文冒号、忽略空格）：

| 标准字段 | 可识别的表头 |
|---|---|
| product | 商品名称 / 商品标题 / 宝贝标题 / 商品 / 品名 / product / title |
| code | 编码 / 商品编码 / 商品ID / 商品id / 货号 / sku编码 / code |
| sku | 商品SKU / SKU / sku / 规格属性 / 商品规格 / sku属性 / 规格 |
| sales | 销量 / 销量(件) / 近30天销量 / 累计销量 / 销售数量 / sales |
| order | 订单编号 / 订单号 / 订单id / 订单ID / 子订单编号 / order_id |
| amount | 订单金额(元) / 订单金额 / 实付金额 / 支付金额 / 成交额 / 付款金额 / amount |
| pay_time | 付款时间 / 支付时间 / 下单时间 / 订单创建时间 / 成交时间 / pay_time |
| issue_time | 首次问题发生时间 / 问题发生时间 / 问题时间 / 投诉时间 / 工单创建时间 / 售后申请时间 |
| issue_type | 问题类型 / 问题一级分类 / 体验问题类型 / 一级原因 / issue_type |
| issue_detail | 问题详情 / 问题二级分类 / 问题原因 / 二级原因 / 问题描述 / issue_detail |
| dept | 问题部门 / 责任部门 / 受理部门 / 归属部门 / 处理部门 / dept |

**必须有的字段**：付款时间（或下单时间）、问题类型（或问题详情）。缺了会直接报错并打印实际表头。

**没有也能跑**：商品名称、SKU、销量、金额、部门 —— 缺了对应章节会自动省略。

## 自定义规则

建一个 JSON，键是阶段名，值是关键词数组：

```json
{
  "S1 售前呈现": ["尺码不符", "面料", "色差", "版型"],
  "S2 下单支付": ["差价", "优惠券", "超卖"],
  "S3 履约发货": ["延迟发货", "漏发", "虚假发货"],
  "S4 物流配送": ["派送停滞", "丢件", "快递"],
  "S5 收货体验": ["开线", "起球", "掉色", "异味", "做工"],
  "S6 售后维权": ["退款", "客服", "差评", "求助平台"]
}
```

```bash
python scripts/analyze.py --input orders.csv --rules my_rules.json --output metrics.json
```

**写规则的三个提醒**
- 顺序写对：数组顺序 = 匹配优先级，越上游越靠前
- 长词优先：先写「派送停滞」再写「派送」，否则长词永远匹配不到
- 每个阶段至少留 3 个词，太少的规则会导致大量 S0 未分类
