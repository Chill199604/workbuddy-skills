# 判读手册 · 指标口径、常见误判、汇报话术

## 一、指标口径

| 指标 | 算法 | 坑 |
|---|---|---|
| 问题订单数 | 去重后的记录条数 | 一单多问题会重复计数，先确认是否按订单去重 |
| 涉及金额 | 问题订单金额求和 | 是**风险敞口**，不是实际损失；退款成功才算真损失 |
| 客单价 | 涉及金额 / 问题单量 | 高客单商品被投诉，金额影响大但单量小，别只看单量 |
| 问题率 | 问题单量 / 销量 | ⚠ 销量常被导出为 **SKU 累计销量**，分母虚高导致率虚低。**口径不明就不要报率** |
| 平均爆发天数 | 付款 → 首次问题发生 | 看**中位数**比平均数稳，个别极端值会拉偏均值 |
| P90 爆发天数 | 排序后第 90 分位 | 用来定售后主动介入的时点 |
| 单周最高占比 | 最多问题周 / 总问题量 | 判断批次性 vs 结构性的依据 |

## 二、问题性质判定

| 单周最高占比 | 判定 | 该怎么查 |
|---|---|---|
| ≥ 40% | 批次性 / 集中爆发 | 查该周的来货批次、活动波次、发货节奏 |
| 25% ~ 40% | 阶段性 | 与销量波次对照后再定（卖得多自然问题多） |
| < 25% | 结构性 / 长期存在 | 流程或商品固有缺陷，单次整改无效，要改机制 |

**中位爆发天数的含义**

| 中位天数 | 说明 | 应对 |
|---|---|---|
| ≤ 3 天 | 收货前后就炸 | 商品/发货端问题，客服端拦截无效，必须前置整改 |
| 4 ~ 14 天 | 使用中暴露 | 质量/耐用性问题，抓来货质检与供应商 |
| > 14 天 | 长期后才出问题 | 耐用性或售后响应问题，看质保与维修链路 |

## 三、常见误判（踩过的坑）

**坑 1：把「受理部门」当「根因部门」**
平台字段里的「问题部门=客服部」，只说明客服在处理。退款类问题根因常在上游。
→ 用法：看报告第 2 章的「疑似误挂条数」，> 0 就要在汇报里点破。

**坑 2：拿宽泛词下结论**
「售后-退款问题」≠ 客服问题。看到这种词就当结论，等于把上游的锅扣给客服。
→ 用法：低置信条数是多少，就承认多少不确定。

**坑 3：样本太小当结论**
单品 < 20 条问题单，分布很不稳定，一个订单的变化能让占比跳动 5 个百分点。
→ 用法：样本小时只说「线索」，不说「结论」，建议扩到 90 天再看。

**坑 4：只看单量不看金额**
10 单 ¥200 的和 2 单 ¥5000 的，金额后者大 5 倍。整改优先级要两个都看。
→ 用法：报告第 7 章的优先级是按「单量 × 金额」加权排的。

**坑 5：把 SKU 高销量当成 SKU 有问题的证据**
卖得多的规格，问题数自然多。
→ 用法：SKU 归因只能用来**定位抽检重点**，不能直接下「该规格有缺陷」的结论，除非能拿到该规格的销量做分母。

**坑 6：问题率下降就当改善**
可能是销量涨了稀释了分母。
→ 用法：同时看绝对值和占比。

## 四、汇报结构（管理层 / 面试都适用）

```
结论（30 秒）
├─ 问题集中在哪个环节
├─ 根责在哪个部门（不是受理部门）
└─ 影响多少金额、多少订单

证据（2 分钟）
├─ 阶段分布：占比 + 金额
├─ 责任穿透：受理 vs 根因的错位
├─ SKU 归位：落在哪些规格
└─ 爆发节奏：批次性还是结构性

动作（1 分钟）
├─ 谁改（责任部门）
├─ 改什么（具体动作）
└─ 怎么验收（指标 + 周期）

局限（30 秒，主动说）
├─ 样本量
├─ 低置信项有几条
└─ 口径假设
```

**主动说局限是加分项，不是减分项。** 面试官问「这份分析有什么问题」时，你能自己先说出来，说明你懂数据而不是只会跑数。

## 五、与其他分析的边界

| 场景 | 用哪个 |
|---|---|
| 体验问题归因、差评投诉根因、责任划分 | **本技能** |
| 退货率趋势、多时段/跨平台对比 | `ecommerce-return-rate` |
| 退货造成的利润损失、修复方案 | `ecommerce-returns-profit-recovery` |
| 活跃度趋势、用户行为 | `user-behavior-analytics` |

三个可串联：**退货率发现异常 → 体验问题分析定位根因 → 利润修复算钱**。

## 六、拿到报告后必做的两件事

1. **翻第 6 章明细表**，把「置信=低」的订单逐条回溯原始聊天/工单，补录真实根因后重跑
2. **看第 2 章责任穿透**，若客服部误挂 > 0，汇报时明确说「这些不是客服的问题，根因在 XX 环节」

跳过这两步直接交报告，就是把推断当事实 —— 会被懂行的人一句话问倒。
